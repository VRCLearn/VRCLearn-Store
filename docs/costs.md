# 费用与容量

## 已确认的账户事实

2026-10-26 使用 `cf` CLI 只读查询：Workers Paid 基础费为 5 美元／月，R2 已启用；`vrclearn.com` 为 active Free Website zone，该域 Email Sending 已启用。现有 Pages、D1、R2 列表中没有本商店的专用资源，其他项目资源保持原样。

账单 V1、V2 和 billable metrics 接口均返回 403；账户列表、订阅、zone、Pages、D1、R2 和发信域读取正常。因此没有判定整个登录失效，也没有从订阅价格推断本月实际用量。

## 成本控制的能力边界

- Pages 静态请求不执行 Functions；动态 API、详情和 sitemap 仍产生函数、数据和配额调用。
- 公开详情内部缓存最多 60 秒；命中减少 D1 和渲染工作，不代表函数请求免费。
- 正常业务目标是每月 10–20 美元，包含 Workers 基础费；同账户其他项目消耗共享套餐包含额度，无法单凭商店请求量给出独立账单保证。
- 运行时成本源为真实 `billable-usage`，按账户累计、目前按日更新，不能提供项目级十五分钟实时费用。需要所有相关产品覆盖、美元计费、合理时间和无截断；不能证明完整时停止高成本功能。
- 10／15／18 美元阈值分别触发告警、受限、维护，只升级不自动恢复。接口 403 时保持受限，生产环境不能依赖当前成本源直接开通上传和新发布。
- 该机制不是 Cloudflare 账单硬上限。边缘拦截、应用配额、CPU、存储预留和人工紧急规则共同降低风险。

官方来源：[Pages 计费](https://developers.cloudflare.com/pages/functions/pricing/)、[Workers 计费](https://developers.cloudflare.com/workers/platform/pricing/)、[R2 计费](https://developers.cloudflare.com/r2/pricing/)、[Email Service 计费](https://developers.cloudflare.com/email-service/platform/pricing/)。上线时复核价格和包含额度，不把此文档中的目标金额当成固定产品价格。

管理员撤权与封禁每次处理最多 200 件商品，与每店铺配额一致。商品库超过 10,000 件时须扩展 sitemap 分片；不得静默截断目录并宣称完整。

## 验证证据

`npm.cmd run test:capacity` 建立 100 店铺／10,000 商品的 SQLite 数据集，验证类别查询使用 publications 索引，中日文二元词搜索使用 FTS 虚表索引，游标分页不重复，原币种价格排序正确。它证明本地 SQL 查询形态，不代表 Cloudflare 实际延迟、计费行数或攻击流量成本；这些需在授权的隔离部署读取 D1 meta 和使用指标验证。

账单 API 权限与来源完整性、实际发信、D1 计费指标、Worker CPU、跨地区边缘规则和紧急规则均为尚未完成的真实环境验收项。
