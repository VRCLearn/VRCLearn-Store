# 费用与容量

## 已确认的账户事实

2026-10-27 的部署记录已确认：`vrclearn.com` 为 active Free Website zone；商店专用的 Pages、辅助 Worker、D1、R2、KV 和 SQLite 配额 Durable Object 已部署，资源 ID 已写入配置。账户已有 10、30、50 美元的预算邮件告警。原生预算告警只计算使用费，不包含固定订阅，也不会暂停服务。Workers Paid 基础费按已核实的 5 美元／月预留。

使用单独的账户 Billing Read 令牌后，`cf` 的 V1 与 V1 info 已读取成功：账户 `covered=true`，一个订阅，默认 V1 返回 233 条美元记录。账单读取令牌与独立的目标 zone WAF 紧急停机令牌均于 2027-01-25 到期，在开发机器以当前 Windows 用户的 DPAPI 加密保存，并分别注入辅助 Worker 的 `CF_MONITOR_TOKEN`、`CF_API_TOKEN`。默认 OAuth 仍不含 Billing 权限；V2 和 billable metrics 使用账单令牌仍返回 403／1171，尚未确认其额外访问条件，当前监控不依赖这两个入口。D1、R2、KV 的最近一小时 SQL Analytics 计数查询也已成功；这些产品指标尚未接入运行时监控。

真实 V1 默认响应同时包含上一账期和当前账期；显式指定 2026-10-26 至 2026-10-27 可只返回当前账期的 13 条记录。监控从 info 的订阅锚点计算当前账期，显式传入 `from`／`to`，不依赖接口默认日期范围；返回记录仍逐项校验账期。

## 成本控制的能力边界

- Pages 静态请求不执行 Functions；动态 API、详情和 sitemap 仍产生函数、数据和配额调用。
- 公开详情内部缓存最多 60 秒；命中减少 D1 和渲染工作，不代表函数请求免费。
- 正常业务目标是每月 10–20 美元，包含 Workers 基础费；同账户其他项目消耗共享套餐包含额度，无法单凭商店请求量给出独立账单保证。
- 运行时先读取 `billable-usage/info`，再按明确的当前账期读取 `billable-usage`，每次最多两个源请求，分别有 10 秒超时和 2 MiB 响应上限，最多 5,000 条记录，不重试。日期窗口从最早的有效订阅账期起点至 UTC 次日；账期按订阅锚点及月末对齐。每项计费指标的最新记录都须在 36 小时内，记录须为美元、含非空计量描述与单位，且没有分页截断。订阅标识缺失时只接受唯一、无歧义的订阅。
- 正常模式依据 `covered=true` 的账户覆盖声明及完整、有效的当前账期响应，保存 `coverageBasis: "provider-account"`。Cloudflare 将 V1 定义为覆盖账户所有按量产品的费用源；`coverage` 仅列出响应中实际识别到的产品族，没有 Logs 行不能解释为已核实日志费用为零。未知产品的有效计费行仍计入账户总额。[Billable Usage API 合同](https://blog.cloudflare.com/billable-usage-api/)
- V1 按账户累计、目前按日更新，不能提供项目级十五分钟实时费用。10／15／18 美元阈值分别触发告警、受限、维护，只升级不自动恢复。覆盖声明无效、响应为空、源接口 403、错误币种／账期、截断或指标过期时至少受限；KV 读取失败、状态畸形或无法持久化新状态时进入维护，并独立尝试边缘封锁。上传和新发布还要求部署后的监控持续写入有效、未过期的状态。
- 该机制不是 Cloudflare 账单硬上限。边缘拦截、应用配额、CPU、存储预留和人工紧急规则共同降低风险。
- 紧急停机在验证两条预配置裸 block 规则后，保留原 action、expression 及存在的 description／ref，仅将 enabled 改为 true；不发送规则顺序或 API 管理字段。Rulesets API 更新须携带要保留的完整定义；遇到额外动作参数等未支持设置时拒绝更新该条，再通过读回确认实际封锁结果。[规则更新合同](https://developers.cloudflare.com/ruleset-engine/rulesets-api/update-rule/)

官方来源：[Pages 计费](https://developers.cloudflare.com/pages/functions/pricing/)、[Workers 计费](https://developers.cloudflare.com/workers/platform/pricing/)、[R2 计费](https://developers.cloudflare.com/r2/pricing/)、[Email Service 计费](https://developers.cloudflare.com/email-service/platform/pricing/)。上线时复核价格和包含额度，不把此文档中的目标金额当成固定产品价格。

## 首期配额

| 操作 | 默认上限 |
| --- | --- |
| 公开未缓存读取 | 每 IP 60／分钟、1,000／日，全站 45,000／日 |
| 上传 | 每账户 100／日，全站 1,000／日，月上传字节 2 GiB |
| 存储 | 私有与公开副本合计预留 8 GiB |
| 图片 | 每商品展示最多 10 张，保留上传最多 30 张；每张 2 MiB，单边 8,192 像素且最多 1,600 万像素 |
| 商家商品 | 每店铺最多 200 件，创建时原子检查 |
| 修订内容存储 | 商品与店铺资料合计：每店铺 2,000 条／32 MiB，全站 100,000 条／1 GiB；按 JSON 的 UTF-8 字节原子计量 |
| 发布提交 | 每账户 20／日，全站 1,000／日 |
| 普通账户发信 | 每邮箱 1／分钟、5／日，全站 100／日、2,500／UTC 日历月 |
| 运维发信 | 另计 6／日、40／UTC 日历月，按状态和日期去重 |
| 查询 | 关键词 2–80 字符，列表默认 24、最多 48，游标分页 |

配额使用 SQLite Durable Object 事务账本，到期时间有索引，最多保存 100,000 条计数与预留记录。获批操作写入前最多清理 32 条过期记录；超限与重放不执行清理删除。Alarm 每次最多删除 1,000 条，积压时最短 60 秒后继续，否则睡到下一到期时间，账本为空后停止调度。达到容量上限或持久化失败时不放行操作，事务回滚所有扣费和清理。普通超限保留 429／Retry-After，重放返回 409，账本容量或服务异常返回 503；配额拒绝前已经产生的 Functions、Worker 和 DO 调用仍有费用。

管理员撤权与封禁每次处理最多 200 件商品，与每店铺配额一致。商品库超过 10,000 件时须扩展 sitemap 分片；不得静默截断目录并宣称完整。

尚未提交且无发布引用的商品草稿、尚未审核的店铺资料在再次保存时替换内部快照，每次生成新的修订 ID；已提交或已审核记录保留。修订存储由 `revision_storage_policy` 集中配置，达到任一限额后拒绝新增或增量写入，同大小或缩小的草稿替换仍可保存。该计量只覆盖两类修订的 JSON 内容，不包含索引、账户、审核日志等其他 D1 占用，不能作为整个数据库或账单的硬上限。

## 验证证据

`npm.cmd run test:capacity` 建立 100 店铺／10,000 商品的 SQLite 数据集，验证类别查询使用 publications 索引，中日文二元词搜索使用 FTS 虚表索引，游标分页不重复，原币种价格排序正确。它证明本地 SQL 查询形态，不代表 Cloudflare 实际延迟、计费行数或攻击流量成本；这些需在授权的隔离部署读取 D1 meta 和使用指标验证。

本地全量 288 项单元／集成测试、52 项桌面与移动端浏览器回归，以及构建、类型检查和部署预检通过。测试覆盖显式账期窗口、账户覆盖声明、缺少产品行时不伪造零值、未知产品费用累计、逐指标时效、源失败、KV 故障、双域停机和读回核验，以及配额清理积压、容量上限、事务回滚、并发与 Alarm 重试。2026-10-27 的 13 条真实当前账期记录已输入运行时同一估算器，本机得出含基础费 5 美元、`normal`、`coverageBasis: "provider-account"`，来源时间为当日 UTC 00:00。CLI 解包数据的本地适配验证不单独证明原始 HTTP 响应完整性，线上来源以实际 Cron 结果核验。

辅助 Worker 当前版本为 `148212b3-faac-48db-b678-d6c35069aeea`，配置 `*/15 * * * *`。2026-10-27 17:15:47 UTC 自动采样已核验：模式 `normal`、估算 5 美元、`coverageBasis: "provider-account"`；实际产品族不含 Logs，没有补造该记录。17:24:36 UTC 读回确认 Pages 仍为 FD 部署、媒体地区 WAF 启用，两条紧急停机规则均禁用。人工恢复已获用户批准并执行，后续自动检查确认正常。自动监控仍只升级模式，不会自动恢复。监控请求采用 `redirect: "manual"`，3xx 直接视为失败，不跟随重定向或转交凭据。

经明确批准的真实停机演练已完成：动态配置 API 与媒体实际返回 403，静态入口保持 Access，已有会话的静态维护页为 200；恢复后两条规则关闭且定义、顺序及其他规则一致，12 次探测符合预期。真实注册、邮件、密码登录、MFA、管理员、商家、商品发布、图片、搜索、收藏及举报处理已有证据。同一商品修订期间保留旧版、两区统一切换、单区下架保留另一地区，以及下架后的商品 API／HTML／搜索／收藏／sitemap／公开图片撤销均已实测；下架验收时公开图片记录清零，私有原图保留一份。最终分区验收又确认 CN 首先生效而国际区待审、国际出口无法读取商品；国际区随后正常通过审核，当前修订 `4be2d32a-d48f-4586-ae98-85d8e59c81a0` 保留双区有效上架及两份公开图片供内测使用。发布和换版未触发 Pages 构建。
