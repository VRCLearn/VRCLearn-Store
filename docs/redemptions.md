# 卡密兑换

## 用户流程

商品页的“购买兑换码”打开商家设置的 HTTPS 网页，链接随商品内容审核。付款与售后由商家处理，商店不接入支付。免费商品同样使用商家提供的卡密兑换。

点击“兑换”后，登录商店账户，输入兑换码并完成人机验证。兑换成功后显示该张卡密对应的独立文本或链接，可复制保存。交付内容按纯文本显示，不执行 HTML、脚本或自动访问其中的地址；商店不托管模型文件。

账户的“我的兑换”支持分页查看已领取内容。仅显示领取地区与当前访问地区一致、且商品当前仍在该区获批公开的记录；商品下架、权限撤销、封禁或 Adult 限制会隐藏相关记录。同一账户在同区重复兑换同一卡密返回原记录，不会再次核销或领取另一份内容。

## 商家导入

保存商品草稿后，展开商品编辑页的“兑换码管理”。公开店铺资料以及至少一个区域的发布权限须已获批；无需等待商品上架即可准备库存。库存属于该商品，不随商品修订复制。

选择 JSON 文件或粘贴 JSON 数组，每个对象只含 `code` 和 `content`：

```json
[
    {
        "code": "REPLACE-WITH-UNIQUE-RANDOM-CODE",
        "content": "https://example.com/your-private-download\n提取说明：请替换为该卡密独有的交付内容。"
    }
]
```

示例值必须替换。卡密区分大小写，去除首尾空白，长度 8–128 字符，不允许控制符或不可见字符；建议使用足够长的随机值，避免顺序编号和可猜测词。交付内容去除首尾空白，每条最多 4,000 字符，支持换行。平台仅保存商品范围内的卡密摘要，原始卡密不能导出，商家须自行保留源文件并在外部店铺销售。

每批 1–100 条，整个 API 请求（包含验证令牌）最多 128 KiB。同批或已有卡密重复、容量不足或权限变化时整批拒绝，不部分导入。每商品累计最多 10,000 条，每店铺 50,000 条，全站 100,000 条；已兑换记录也计入累计容量，避免通过核销绕过存储上限。本轮不提供库存删除、自动过期或商品文件存储。

导入结果不明时先刷新库存核对；平台不自动重试导入。库存接口只提供总数、可兑换数与已兑换数，不返回卡密摘要或交付内容。用户领取后内容仍保存于私有表，公开商品接口、详情 HTML、推荐、收藏及商家工作台数据中均不包含它。

## 限制与原子性

导入、兑换均要求登录、同源请求、Turnstile 和业务原子配额，配额服务异常时停止操作。导入每账户每小时最多 10 次、每日 1,000 条，全站每日 10,000 条。兑换每账户每分钟 6 次、每日 100 次，每 IP 每分钟 20 次，全站每日 5,000 次；失败尝试也占用额度。

数据库条件写入同时检查商品归属、容量或当前发布权限，不依赖页面状态。核销使用条件更新，一张卡密只会被一个账户领取。当前商品可见性和领取地区在同一 SQL 中校验；私密响应使用 `Cache-Control: no-store`，不进入公共 HTML 缓存。日志与错误响应不记录卡密或交付正文。

迁移只新增 `redemption_codes` 表及索引，不改写已有商品、账户或迁移历史。本地测试使用独立内存 SQLite、Miniflare D1 和浏览器 fixture，不导入真实卡密，不操作线上数据。
